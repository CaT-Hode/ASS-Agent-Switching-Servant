# 项目级对话管理与同步

ASS 0.2.14：先用横向胶囊切换本机已识别且支持的 Codex / Claude Code / DSH / OpenCode / pi，再按项目聚合会话。项目按规范路径识别，不因名称相同合并；Codex 优先采用桌面保存的项目归属，显式无项目记录不因工作目录而参与同步。

三栏边界可拖动，松开后保存宽度；方向键微调，Shift 加大步长，双击或 Home 恢复当前栏默认值。保留正文最小空间，窗口变小时约束栏宽。滚动条使用原生滚动和细圆角滑块。

单一搜索入口匹配当前客户端的项目名、路径、对话标题和原生会话 ID。项目名或路径命中时保留该项目全部对话；只有标题命中时显示匹配的对话。搜索只读已发现的元数据，输入不会重新扫描历史、同步原生内容或传输正文。置顶筛选有独立方形按钮和悬停 / 键盘说明。项目列表采用紧凑两行，中间不再重复显示项目大标题。

Codex 名称优先采用索引中的 `name`，然后为 `title`；CC 使用原生重命名记录，DSH 使用 `session/title`，OpenCode/pi 使用各自原生标题。项目归属或名称更新后，即使 JSONL 没有变化也会更新。大 Codex 日志通过分块读取，不再因超过 128 MiB 而被排除；列表扫描只读取元数据，不把全部正文发给前端。

## 开关与内容归属

关闭状态仍可读取、预览、搜索及在原客户端继续，Codex/CC 的 OAuth 历史保留与置顶功能不受影响。只有打开项目右上角“项目同步”后才收集共享正文；可展开“同步客户端”调整参与范围。其他客户端视图及生成的原生记录显示“来自 xxx 的同步”。

切换顶部客户端后，选择项目内对话继续。ASS 在启动前收集已完成新内容，按需生成目标格式，采用当前客户端的凭据；不迁移 OAuth、API Key、插件、系统提示或工具许可。ASS 运行时每 15 秒检查已开启项目。轮流续聊可保持共同历史；并发分叉保留两支，不按时间戳拼接。已经运行的客户端内存上下文不会被在线替换。

关闭开关不是暂停：先收集完成内容及分支，在初始客户端内创建必要的归回记录，然后移除 ASS 生成的跨客户端副本。原始日志不覆盖，独立原生会话不删除。若 ASS 续聊窗口仍在运行、轮次未完成、来源身份或文件变化，清理会停止并保留同步状态。失败可重试，不宣称已经清理。

移除前的副本在 ASS 数据目录 `project-conversations/released`，归回快照在 `returned`，可手动恢复。关闭后清空该项目的共享图；重新开启从现存原生历史重新收集，不复活已移除副本。退出 ASS 不删除原生会话，也不等于关闭项目同步。

## 存储

统一库位于 ASS 数据目录的 `project-conversations`。索引与密钥由 Windows 加密存储保护，共享消息正文采用 AES-256-GCM、按内容哈希去重；重复内容和分支前缀只保存一份，各次时间独立记录。

Codex / CC / pi 的 JSONL 与 DSH 的 Zstandard JSONL 在同卷优先文件硬链接；跨卷或不支持链接时独占创建副本。原生原子替换断开链接后，不覆盖新文件。跨格式需要独立投影，不能把不同格式链接成同一个日志。没有目录级链接，也没有链接认证文件。

OpenCode 只读原生 SQLite，投影使用官方 `import`，关闭同步使用官方 `session delete`；不直接改写活动数据库。续聊、归回和清理需要可用 CLI，只安装桌面端仍可读取。CLI 不可用或清理失败时不会报告关闭成功。

## DSH / pi 适配边界

- DSH：读取已知 v0–v4 事件；正文只提取真实用户输入与助手文本输出，保留 Markdown、代码及文本分段。`user/message` 也可能是模型输入的内部上下文，按 `source.kind` 区分：用户输入为 `user`，助手输出为 `model`，显式其他来源不作为对话正文；旧记录缺少来源时保留兼容，同时检查显式角色。系统 / developer 消息、环境 / 时间上下文、技能说明及其他注入、工具调用 / 返回、思考、压缩摘要与附件占位符不显示或收集为对话正文，也不作为后备标题。元数据缓存记录解析规则版本，升级后即使文件未变化也重算标题；原生预览重新解析正文，原始文件只读。兼容替换范围及拼接 Zstandard 多帧日志，校验完整帧，忽略正在追加的残缺尾帧；不再只读第一帧的会话头。写入 v3，经官方严格恢复器验证，由新版原生客户端处理其升级。未知 v5+、损坏记录不强行转换，未完成轮次不跨客户端传输。当前 web profile 启动后仍需在 DSH 会话列表选择提示的会话 ID，尚未自动跳转。
- pi：v1 线性记录只在内存中规范化；v2/v3 按活动父链读取。系统提示、扩展授权和用量记录不误当助手消息同步；未完成工具轮次留在来源。原树分支仍在原日志。
- pi 支持 `PI_CODING_AGENT_SESSION_DIR` 自定义目录；续聊显式指定文件与会话目录。若当前 `settings.json` 配置了默认供应商/模型，启动采用它们而不是历史模型元数据。
- 新账户的模型权限仍由原生客户端决定。历史工具操作是不可执行的文本上下文，不会重放调用。附件实物仍在来源存储，跨格式只保留来源说明，不承诺附件/插件零损失迁移。

格式依据：[pi 会话格式](https://pi.dev/docs/latest/session-format)、[DSH 会话系统](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/README.md)、[OpenCode CLI](https://opencode.ai/docs/cli/)、[Claude Code 会话](https://code.claude.com/docs/en/sessions)。Codex 适配依据公开实现及本机隔离 CLI 验证；仅解析文件不等于原生续聊验证。

## 删除与恢复

列表右侧的小垃圾桶删除对应客户端本地对话；项目垃圾桶删除该分组所有客户端的对话，不删除项目目录或代码。先关闭项目同步，点击附近的小确认窗口后才删除。Windows 上已确认使用 Codex 0.162+ 后端时，原生归档对话可以在 Codex 运行中删除；当前对话、其他客户端记录与恢复操作仍要求相关客户端关闭。不会为了删除自动强制关闭客户端。

运行中归档删除沿用 Codex 的 `thread-writer-locks/.coordination.lock` 与逐线程 OS 写入锁，持有到删除完成，防止恢复或新写入与删除竞争。仍被客户端占用的归档目标、恢复为当前对话的记录、被其他分支引用的历史、未经确认的后端版本及无法取得锁的情况拒绝删除；闲置锁文件不会被当作运行进程，也不会强删锁文件。依据 [Codex 写入锁实现](https://github.com/openai/codex/blob/rust-v0.162.0-alpha.2/codex-rs/rollout/src/writer_lock.rs)。不是绕过进程检查，也不调用会级联删除子代理的 `thread/delete`；继续使用下述单记录、可恢复的删除范围。Codex 已打开的列表可能需要刷新。

引用检查包含隐藏子代理目录；遇到无法解析的会话头、压缩历史或超出扫描范围时不在运行中删除，需要关闭 Codex 后操作，避免漏掉未知引用。

运行中不重写共享的 `session_index.jsonl` 名称文件，避免与其他对话重命名竞争；仅保留该旧名称条目，不保留对应的原生日志或线程索引行，也不会因此在列表重新出现。该条目可在恢复时复用。

置顶与垃圾桶使用固定宽度的居中操作列，不以标题行数决定位置。垃圾桶图标为 14px，按钮为 22px、无边框；悬停掀盖、按下投纸、移出复位，仅动画图标内部部件。删除及恢复的结果使用与客户端接入相同的右下角通知，失败不占据页面顶部空间，也不隐藏原记录。

关闭判定正确读取系统适配器返回的单项结果列表；运行中的客户端、无法解析或失败的检查仍阻止删除。内容按 CommonMark / GFM 渲染，包括标题、引用、列表、任务项、表格、行内与围栏代码。只是显示格式变化，不改写原日志和共享消息。历史 HTML 作为文本显示，文件和脚本链接不可执行；外部图片只有点击后才加载。

点击垃圾桶后只出现一次邻近二级确认，提示“不保存备份，无法撤销”；确认后直接删除，不创建 `project-conversations/trash` 恢复副本、不加密复制正文，也不保存 OpenCode 恢复 bundle。仅记录会话 ID 与操作进度等小型元数据，避免已删除内容在重启后从旧索引重新出现；这不是内容备份，不能用于恢复。

Codex 只移除对应线程的索引行及名称条目（运行中保留共享名称条目），不替换整个数据库或级联删除其他运行时表；CC 更新对应会话的名称条目，DSH 移除同一会话的旧格式文件以免回退后复现，OpenCode 通过原生 CLI 删除。文件身份与正文哈希变化时停止；失败可能已完成部分删除，该部分不能从本次操作恢复。Codex 的 `thread_history_*.sqlite` 正文存储、远端副本及此前主动保留的历史不在此删除范围内，不将此功能宣称为所有副本的隐私擦除。

已有旧版备份不会自动清除，顶部“已删除记录”仍能恢复这些旧记录，重启 ASS 后也可使用；新的删除不进入恢复列表。旧备份恢复到原位置，已有同名但不同内容的文件或同 ID 的不同索引不会覆盖；OpenCode 通过原生 import 恢复。对话删除与账号切换保留是独立功能，OAuth 凭据不参与删除。
