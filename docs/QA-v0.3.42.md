# v0.3.42 恢复与启动验证

## 复现

通过 v0.3.41 已安装包中的配置模块、启动模块与新代码对照，隔离复现以下行为：

- 旧接入没有加密 attachment 副本且 canonical 记录丢失时，原代码出现“Codex 接入记录缺失，且没有可信的已应用副本”；已有原始 TOML 备份也不能恢复。
- 可选中转准备抛出同一错误时，原启动按钮不调用本机启动入口。
- 已有 Codex 进程时，原启动函数返回成功提示，但不调用本机入口唤起窗口。

新代码对照复现全部通过，无远程请求。现场只读取必要元数据，确认当前磁盘 OAuth 登录存在、现存接入记录可校验、旧版已应用记录未包含 attachment；不能据此断言用户上次报错发生时的文件状态完全相同。

## 恢复覆盖

- 缺少 canonical 与旧版 attachment：从唯一原始备份恢复，第三方未应用草稿不进入路由。
- 缺少 canonical、原始备份与旧 attachment：使用独立加密检查点；检查点损坏时尝试前代。
- canonical JSON 半写：保留原始字节到加密恢复备份，事务恢复记录，重复启动不重复写入。
- 原生写入器移除全部或部分标记：完整连接字段与可信记录一致时重建标记，保持 TOML 语义、最新模型选择和 OAuth 字节不变。
- 备份歧义、其他目录的检查点、外部连接地址变更、未知有效 JSON 格式或回滚基线被改动：保留现场，不猜测回滚值。
- ENOSPC、并发新路由、恢复重试：原生配置和凭据不变，不覆盖外部新数据；可选检查点失败不会阻断已有效的 OAuth 接入。
- 检查点每份最大 1 MiB，保留当前和前代；旧备份最多检查 64 个、单份最大 1 MiB、累计读取最大 8 MiB。不同原始备份的恢复值冲突时拒绝猜测。
