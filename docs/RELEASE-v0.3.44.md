# v0.3.44

修正 Windows 打包应用启动的子进程可能继承 AppData 重定向、导致 ASS 从不同入口读取两套配置的问题。启动时同时核对已有数据文件和新文件写入的实际位置；遇到重定向，通过现有 Windows 桌面的启动环境重新打开 ASS，再加载加密密钥和配置。桌面启动失败或再次重定向时明确停止，避免继续写出另一套数据。显式指定的数据目录和非 Windows 平台保持原行为。

本机已核对物理目录与重定向副本，并完成以下恢复：

- 将缺失的 WOYAO 及其 5 个模型恢复到实际运行目录，按目标目录的加密密钥重新加密凭据。
- 核实 10 条 DSH/Pi 接入字段与当前原生配置完全一致，再恢复归属记录；恢复 Codex 已应用状态、管理区段记录、对应目录和原配置备份。
- 保留实际目录中的现有 DSH 模型、用户偏好、客户端选项和历史；恢复另一份目录独有的会话保留索引。原生配置及 OAuth 文件哈希未改变。
- 已生成一份含校验清单的恢复备份，重复目录已改名隔离。永久删除被执行环境的自动审批策略拦截，未据此声称释放了其占用空间。

验证：102 项相关回归通过，其中 6 项覆盖正常目录、已有文件重定向、新写入重定向、桌面接力、失败及重复启动、显式目录隔离。使用隔离假数据，不发起远程模型请求。

另外对本机恢复后的数据完成 Electron 实际解密核验，并使用生产 React 供应商组件渲染其公开快照：OpenAI 官方 4 个模型、DSH 原生 1 个模型、WOYAO 5 个模型，共 3 个来源；WOYAO 搜索通过，没有重复原生来源或 renderer 异常。验证视口为 1440×1000、1100×900。该验证使用独立的隐藏 renderer，没有操作用户正在运行的 ASS 窗口，也未重新查询远程余额。

Windows 桌面接力已通过本机只读辅助进程确认，其访问的是物理配置目录。运行包包含 150 个文件，未发现测试、QA、私有数据或令牌形状源码。开始菜单已固定指向 0.3.44，原运行进程保留，由用户自行重启。Windows 只生成一个安装 EXE，不生成 ZIP；源码未提交或推送。

未验证：用户重启后的实际窗口、真实 OAuth 登录及远程调用、Windows 安装向导、其他打包启动器或组织策略下的桌面接力行为。没有运行全量测试集。
