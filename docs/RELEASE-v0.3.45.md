# v0.3.45

修复 DeepSeek 原生 Responses 接入中的 Codex 工具兼容问题。原实现仅对 Chat Completions 和 Anthropic 做命名空间及自定义工具转换，直接透传的 DeepSeek Responses 请求缺少这层适配；注入目录也继承了官方模型的 Responses Lite 标记，并写入了与 DeepSeek 官方接入示例不同的 `tool_mode`。

- DeepSeek 原生 Responses 的命名空间和自定义工具转为可接收的 JSON 函数，返回时恢复 Codex 的工具名称、命名空间及原始输入；JSON、SSE、工具历史和指定工具选择保持对应。
- 原生推理条目仍按 Responses 格式保留，支持工具调用后的继续请求。失败任务、流提前断开及无效自定义输入不能被记录为正常完成。不从 DSML 正文猜测并执行工具调用。
- 按 [DeepSeek 官方 Codex 接入文档](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/) 修正工具协议字段：`tool_mode = null`、`use_responses_lite = false`、`apply_patch_tool_type = freeform`，并关闭 WebSocket 偏好、启用相应的并行工具和原生推理元数据。保留用户的模型 ID、上下文长度和默认思考强度。
- 已应用的旧目录可通过受保护的目录刷新事务更新兼容字段；不发布未同步的供应商草稿，不修改官方订阅模型元数据、OAuth、原生客户端配置或当前默认选择。外部目录变更仍拒绝覆盖。
- 在“客户端注入 → Codex → 展开供应商 → 模型列表”增加“Codex 工具兼容”，提供“自动识别 / 兼容模式 / 原生格式”。自动模式按真实服务地址识别 DeepSeek，兼容模式可用于其他 Responses 服务，原生格式可关闭自动转换。Chat Completions / Anthropic 已经通过 Responses 转换接入，沿用已有工具适配。
- 选项按供应商和模型保存在 Codex 接入草稿中，选择后通过“同步接入”应用；不更改共享供应商模型设置和其他客户端。失败保存回滚内存，模型改名携带选项，删除模型同时清除选项，恢复自动会移除额外记录。官方订阅没有此覆盖入口。

验证范围：129 项后端相关回归通过，覆盖 Responses/Chat/Anthropic 工具桥接、失败任务、截断、重复请求、接入目录迁移、官方历史隔离，以及兼容选项的持久化、失败回滚、同步前后隔离、恢复与重启。新增测试使用隔离假数据及本地模拟请求。另以真实 React DOM / 隔离 Electron 验证模型菜单的选择、保存、失败重试、待同步状态和其他客户端隔离，检查 1100×800 深色与 620×800 浅色布局；截图保存在系统临时目录。

界面测试使用现有 Playwright / Electron（Browser plugin not available）。首轮截图遇到隐藏窗口帧捕获超时；定向检查还发现测试夹具缺少应用已有的 CSP，已使夹具与应用策略一致并为截图等待重绘，之后定向复测通过。夹具调整后的完整界面回归为 17/17 通过，与上述后端 129/129 合计 146 项；页面识别、非空内容、错误遮罩、控制台、截图和交互检查均通过。

打包支持通过 `ASS_ELECTRON_CACHE` 指定已有 Electron 缓存，并使用固定 Electron npm 包附带的校验值验证归档。此次复用的 44.4.3 缓存 SHA-256 已核对匹配，避免环境切换后重复下载运行时；不会把缓存、测试或验证脚本加入运行包。

另以当前 DeepSeek API 执行了极小的合成工具请求：JSON 和 SSE 两种格式均通过完整 ASS 路由返回 `functions.exec` 自定义工具调用，发送模拟工具结果后获得 `ASS_TOOL_CHECK_OK`，原生推理历史可续传。没有执行生成的命令，没有发送原 APK 会话内容，也未替原会话继续逆向任务。该真实检查仅验证小型工具闭环，不代表原长会话已重跑通过。

本机开始菜单入口更新到 0.3.45，当前运行进程保留，由用户自行重启。Windows 只生成一个安装 EXE；运行包不包含测试或私有验证数据；源码未提交或推送。
