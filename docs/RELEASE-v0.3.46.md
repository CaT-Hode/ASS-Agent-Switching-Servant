# v0.3.46

修复旧 Codex 会话切换到兼容模式后，在 ASS 本地返回 HTTP 400“自定义工具历史缺少对应定义”的问题，并按实际异常状态显示“一键修复”。

本轮从用户指定会话的失败记录和 ASS 请求日志确认错误发生在上游请求发出前；只读取了会话中的工具类型、名称和命名空间元数据。旧记录中的 `custom_tool_call` 没有命名空间，而上一版转换要求历史与当前工具声明完全匹配。隔离复现同样返回该 400，随后完成以下修改：

- 历史调用缺少命名空间时，只有当前工具中存在唯一、同名且输入类型相同的工具，才恢复其当前身份。无歧义名称索引一次构建，避免长历史逐项扫描整个工具列表。
- 当前已移除的工具和存在同名歧义的旧调用，按稳定名称转换历史调用及结果，保留输入和 `call_id`；不增加可调用的旧工具定义，不猜测同名工具所属命名空间。无效自定义工具名称或非字符串输入仍显式拒绝。
- 转换仅作用于出站请求，原始会话文件保持原样；不解析或执行 DSML 普通正文。官方订阅继续使用原生历史路径。
- 正常开启、未开启及仅有草稿待同步的接入，不显示“一键修复”和相关提示，也不触发后台修复检查。已有接入异常或普通接入检查失败时仍可修复和重试，迟到的检查结果不能让健康的新弹窗重新出现修复入口。

统一验证：`node --test --test-concurrency=4 tests/protocol-bridge.test.cjs tests/deepseek-responses.test.cjs tests/response-history.test.cjs tests/connection-repair-ui.test.cjs`，42/42 通过。覆盖 910 对合成旧工具调用及结果、重复转换、已移除工具、同名歧义、无效历史、JSON / SSE 完整路由、官方历史隔离、正常与异常修复按钮、失败重试和异步结果隔离。所有请求测试使用虚拟数据和本地模拟，不发送用户原会话内容，不执行生成的工具调用。

界面使用现有 Playwright / 隔离 Electron（Browser plugin not available），在 1100×900 和 1440×900 检查正常接入弹窗。页面身份、非空内容、错误遮罩、控制台、截图及交互检查均通过。构建成功，截图保存在系统临时目录。

本机以 `--keep-running` 更新下次启动入口至 0.3.46，保留正在运行的 0.3.45，由用户自行从开始菜单重启。打包核验 151 个运行文件与白名单源码一致，禁止打包文件和含密钥形态的源码均为 0；仅提供单个 Windows 安装 EXE，不自动提交或推送。

开始菜单普通路径与物理路径均已核验指向 0.3.46；打包后的工具转换源码与当前修复一致。ASS、Codex、Pi、DSH 的关键配置/凭据文件和指定原会话历史文件共 11 个，部署前后 SHA-256 11/11 未变。

未验证：用户重启后的原长会话完整续聊、真实 DeepSeek 上游、Windows 安装向导。此前 v0.3.45 的小型真实工具测试不代表本轮原会话已执行成功。没有向引用会话发送消息，也没有修改其历史或继续其 APK 任务。
