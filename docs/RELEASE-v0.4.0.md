# v0.4.0

修正启动后接入状态误报、客户端状态操作和旧 Codex 工具历史兼容，并整合此前本机维护版本的接入恢复改进。

- 修复重启后明明没有编辑仍显示“待同步”：供应商解密读取产生的 `secrets: undefined` 存储占位字段不再进入路由计划，避免与 JSON 已应用记录比较时产生虚假差异。Codex 自身修改默认模型或思考强度继续视为原生偏好，不触发接入改动；在 ASS 中主动修改默认模型或路由仍需同步。
- “待同步”“接入异常”文字及对应说明直接打开同步/修复确认弹窗。注入开关拥有独立点击区域，只有操作开关才开启或断开接入。
- 活跃请求数移到客户端名称右侧，保留固定位置；请求数在 0、1、多条之间变化时不再增加或移除正文状态行。
- 正常接入或仅有草稿待同步时隐藏“一键修复”，异常及失败重试入口保持可用；迟到的检查结果不能重新显示健康弹窗的修复操作。
- 修复兼容模式遇到无命名空间的旧工具历史时在本地拒绝请求的问题。只匹配当前唯一且输入类型一致的工具；已移除或有歧义的调用保留为历史，不重新注册旧工具定义。包含 910 对合成旧调用及结果的回归。
- Codex 注入模型菜单提供“自动识别 / 兼容模式 / 原生格式”。DeepSeek 原生 Responses 按服务身份自动兼容，其他服务可手动设置；保留官方订阅目录的原生上下文和能力字段。
- 整合可验证的接入记录恢复、未完成事务恢复、启动入口降级、原生供应商去重、持久化保护和 Windows AppData 重定向防护。相关实现及边界见此前维护版本说明。

测试使用隔离数据、模拟请求和独立 Electron renderer；不向引用的会话发消息，不执行其任务或改写其历史。真实长会话续聊、OAuth 登录迁移和 Windows 安装向导不在本轮测试范围内。

本机发布前验证：`npm test` 全量 1046/1046 通过，`npm run build` 成功。重启回归覆盖磁盘读取后的存储占位字段、原生默认模型/思考强度更新，以及 ASS 主动编辑仍需同步。真实 React renderer 验证状态文字与独立开关、请求数变化时正文坐标不变；1100×900 和 1440×900 截图已检查，无横向溢出、遮罩或控制台错误。界面使用现有 Playwright / Electron（Browser plugin not available）。

Windows 仅提供一份安装 EXE，运行包按白名单排除测试、QA 和用户配置。本机替换更新下一次启动入口，保留运行中的进程，由用户自行从开始菜单重启。
