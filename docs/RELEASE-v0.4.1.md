# v0.4.1

连接诊断按失败证据分类，不再把本机通用 502 当成供应商的实际状态。

- 区分 DNS 解析、网络/TLS、认证、额度/余额、请求受限、网关、权限、服务及响应流错误。只有明确的额度错误代码或余额不足信息才判定为额度耗尽；401 说明凭据未被接受，普通 429 不直接判定为余额耗尽。
- 分开显示上游 HTTP 和 ASS 本地 HTTP。DNS 失败显示“未收到”上游 HTTP，可展开查看 `ERR_NAME_NOT_RESOLVED` 等安全错误代码，不推断密钥、额度或 DNS 拦截方。
- 单模型闪电、一键测试、最近请求和重启后的历史记录保留同一分类与操作提示。一键测试不再遮掉单模型的延迟和协议详情。旧版没有保留原因的记录明确标为旧记录，需手动重新检测，升级不会自动请求供应商。
- 支持 HTTP 200 响应流内的明确额度错误。诊断专用错误摘要只保存受限枚举和安全代码，不保存供应商原文、密钥或响应正文。正常客户端请求继续保持既有错误透传行为。

验证使用本地模拟上游、临时加密历史和隔离 Electron renderer，不消耗真实模型额度，不修改 DNS、hosts、代理、供应商配置、登录凭据或现有注入。覆盖诊断失败时另一个持续请求不被取消。桌面深浅色下检查详情展开、闪电提示和重新检测操作。

89 项针对性回归通过（包括主进程 IPC → 单模型/一键测试 → 重启恢复），前端构建通过。最终运行包 153 个运行文件与源码一致，敏感文件扫描通过；隔离正式包启动及页面检查通过，无页面错误。未进行真实云模型调用，也未声称本轮修复了供应商 DNS 或订阅状态。

本机可通过 `node scripts/local-release.cjs install --keep-running --json` 仅更新下一次启动入口。不会退出进程、覆盖正在使用的包或改变 `release/current`。
