# v0.4.14

主导航新增「请求监控」，专门查看经 ASS 路由的模型请求。

- 汇总请求数、实时处理数、成功率、输出 TPS、缓存命中率和平均首输出延迟；趋势展示请求量与输出 TPS，另列输入、输出、缓存读取和写入 token。
- 请求明细可按时间、供应商、客户端、状态或关键词筛选，支持分页、暂停刷新和单条详情；提供模型与供应商汇总。默认不混入连接测试或 token 计数请求。
- 模型名复用现有 `usageModelName`：`ASS_x::vendor/model`、`vendor/model` 与 `model` 合并为 `model`。原始 ID 仅在请求详情中展示，路由 ID 保持原样。
- Codex 与 Harness 路由从上游原始 Responses / Chat Completions / Messages 流采集数字，避免跨协议转换丢失缓存字段。Anthropic 输入统一加上缓存读取与写入。
- 输出 TPS 使用上游报告的输出 token / 首个有效输出到结束事件的耗时，汇总按生成时间加权；缓存命中率按有缓存记录的输入 token 加权。未报告的指标及旧日志的 TPS 显示“—”，非流式响应不估算首输出或 TPS。
- 读取原有两份滚动请求日志，重启后可查看保留记录，内存最多展示最近 5,000 条。仅保存计量数字与路由标签，不保存提示词、回答正文或凭据。直连供应商的原生客户端用量仍在路由总览查看。

验证涵盖三种协议的计量、原始字节透传、缓存与加权归并、历史恢复、筛选与暂停刷新，以及桌面浅深色布局。打包程序的导航和生产 IPC 使用隔离数据验证。本机安装保留正在运行的 ASS 与 Codex，新版本在下次正常启动时生效。
