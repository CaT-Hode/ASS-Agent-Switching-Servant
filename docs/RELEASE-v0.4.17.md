# v0.4.17

请求监控统一显示「全程 TPS」：全部输出 token（含推理）除以请求全程耗时，包含上传、等待及推理。此前把隐藏推理 token 除以首次输出后的短时间，会显著虚高。例如本机一条 6,085 输出 token、耗时 318.686 秒的请求，旧值约 3,873.3 TPS，修正后约 19.1 tok/s。这是客户端侧全程吞吐，不能直接当作服务端解码速度。

- 实时请求首秒先采样，随后按累计总耗时更新。字符估算继续标记「≈」，结束后用上游实际用量结算；同一事件包含用量与文本增量时不再重复估算。
- 明细、详情、模型及供应商汇总、趋势图采用相同口径。历史汇总用成功请求的输出 token 总数除以这些请求的总耗时；并发卡片明确标注为各活跃请求全程吞吐之和。
- 旧历史有输出 token 与总耗时即可在读取时重新计算，缺少字段显示「—」。原日志、Token 用量、模型最后一级归并保持原样；首输出延迟与首输出后耗时独立显示。非流式响应可计算全程吞吐，不虚构流式时间。
- 修正此前超时处理扩大的错误码范围：普通 SSE 中断继续使用原有 `stream_failed`，超时使用专用错误码。

回归覆盖隐藏推理、首次采样、同事件用量、Responses / Messages / Chat 流式透传、历史读取与汇总，以及实际打包界面。精简检查确认只需现有数字计数与总耗时，无需滑动窗口、速率上限或新的采样缓存。本机安装保留当前 ASS 与 Codex 进程，在下次正常启动 ASS 时生效。
