# v0.4.18

主要 TPS 改为「可见输出接收速率」：非推理输出 token 除以首个至末个可见文本或工具参数输出的接收时长。首次可见输出前的等待、推理摘要，以及最后输出后的用量尾包延迟均不纳入该时长。它衡量客户端接收表现，不能直接还原服务端解码速度。

- 上游在同次用量报告中明确提供输出与推理 token 时，使用两者之差；其他情况下仅对可见内容做字符估算，并标记「≈」。估算不进入计费用量。实时值需观察到不同时间的可见输出，采样一秒后显示；输出之间的停顿仍计入实时接收时长。
- 明细、详情、模型 / 供应商汇总及趋势采用同一口径。历史汇总以成功请求的可见 token 总量除以对应接收时长之和，有估算样本时一并标记。并发卡片为活跃请求的可见接收速率之和。
- 全程吞吐保留在请求详情中，继续使用全部输出 token / 请求总耗时。总输出、推理与可见输出单独展示，模型名称继续沿用最后一级归并。
- 原日志不改写。旧记录没有独立可见输出计时、单包缓冲或非流式响应，主要 TPS 显示「—」，可查的 Token 用量与全程吞吐保留。同一网络包内多个 SSE 帧共享到达时间，避免把解析时间误当成接收时间。

验证覆盖推理与可见输出的独立计时、工具参数、用量尾包、同事件增量、单包缓冲、旧记录、估算汇总、流式透传以及桌面深浅色与实际打包界面。对照检查保留必要的数字计数和独立时间，无需保存输出正文、额外分词库或新的采样缓存。本机更新保留当前 ASS 与 Codex 进程，下次正常启动 ASS 后生效。
