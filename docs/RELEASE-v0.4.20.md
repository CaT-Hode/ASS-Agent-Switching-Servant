# v0.4.20

Claude 接入页新增“CLI 默认模型”和“Auto Mode 审查模型”，均从此客户端已纳入的可用模型中选择，允许来自不同供应商。默认模型留空时使用首个已纳入模型；审查模型留空时跟随当前终端模型。

保存后按既有流程同步接入，再打开新的终端。普通接入可点击“启动默认模型终端”；无账号启动开启时，系统终端直接运行 `claude` 也会使用已同步配置。已有终端不强制重启，官方登录凭据保持原样。更改模型名称或删除模型时，选择记录一同更新。

上下文达到 1,000,000 token 的模型，CLI 的注入列表、默认模型、启动参数与审查模型自动附加 `[1m]`；较小上下文保持原名。该标识只用于 Claude Code 选择长上下文，ASS 的模型匹配和上游请求仍使用原始 ID，用量与请求监控按最后一级模型名归并时也移除后缀。

审查模型通过 `CLAUDE_CODE_AUTO_MODE_MODEL` 写入，并映射 `ANTHROPIC_DEFAULT_SONNET_MODEL` 兼容旧版 CLI，因此旧版的 `sonnet` 别名也使用审查模型。`CLAUDE_CODE_AUTO_MODE_SERVER=0` 让 CLI 自己发起模型审查，以使用指定模型；不改变权限模式、权限规则或工具审批要求。按 Claude Code 官方文档，独立审查模型变量需要 2.1.302+；本机 2.1.283 通过 Sonnet 映射验证。见[官方说明](https://code.claude.com/docs/en/permission-modes#choose-the-classifier-model)。

配置仍区分草稿与已应用状态；一键修复读取已应用模型；退出无账号模式或关闭接入时恢复原字段，包括原有审查模型与服务端审查选项。

验证覆盖配置保存、同步、独立模型路由、重命名与恢复，以及打包后的选择界面。原生 CLI 验证使用临时目录、两个本地模拟供应商和自动审查后的工具执行，不使用真实云端凭据。消融试验移除 Sonnet 映射后，本机 2.1.283 的审查回退到主模型，确认该兼容映射需要保留。

本机以 `install --keep-running` 安装，新版本在下次正常启动 ASS 时生效，当前 ASS 和 Codex 保持运行。
