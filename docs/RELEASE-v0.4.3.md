# v0.4.3

修复开启 Codex 提示词预测兼容后，旧对话仍因绑定 ASS 供应商而被客户端跳过的问题。

- 注入页显示旧对话待修复数量，提供“修复旧对话预测”。需先应用普通 OAuth 预测兼容配置，再正常退出 Codex；ASS 保持运行。用户确认重启 Codex 并更新接入时，也会在客户端停止后修复旧绑定。
- 仅将 ASS 持有的旧对话供应商改为 `openai`，保留原模型、思考档位、聊天正文、工具结果、压缩记录、标题及归档状态。不会切换到官方模型，也不迁移其他工具的供应商。
- 复用会话事务日志及并发校验，额外保留加密恢复备份。Codex 未退出、有请求进行或受管配置发生外部修改时拒绝写入。
- 界面区分开关设置、已应用配置和旧对话绑定，避免将开关开启误报为已有对话预测已恢复。官方功能开放、模型支持和内容检查仍由原生客户端决定。

包含此前未提交的 v0.4.1 诊断分类、v0.4.2 供应商专用 HTTPS DNS，以及无账号模式下旧 Codex 对话的本机凭据识别修复。

用量统计按模型分类时，所有客户端统一使用 `::` / `/` 分隔后的最后一级名称合并。多级供应商前缀和历史缓存适用同一规则；不改原始记录，不丢失 Token、缓存、调用和会话计数。

验证包含回归测试、隔离 React renderer，以及当前安装的 Codex 后端配合虚拟 OAuth 和本地模拟 Responses 服务：修复前创建 ASS 对话，修复后重载，确认供应商为 `openai`、原第三方模型及上下文保留，并完成临时预测分支及结构化输出请求。未验证用户账户的真实远程预测。

本机使用 `node scripts/local-release.cjs install --keep-running --json` 更新下次启动入口，保留当前 ASS 进程及 `release/current`，不会热替换正在使用的资源。
