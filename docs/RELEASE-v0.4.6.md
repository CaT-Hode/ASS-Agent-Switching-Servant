# v0.4.6

修复 Codex CLI 模型目录加载失败，以及 Gemini Anthropic 接入被原生网页搜索声明阻断的问题。

- 新版桌面模型缓存可缺少 CLI 必需的 `base_instructions`、`supports_parallel_tool_calls`。保留 v0.4.5 的兼容实现：使用原生模板补齐旧指令字段，保留已有值及未来字段，不改原生缓存或用户模型偏好。无原生缓存时的备用目录也能被 CLI 加载。
- 已应用目录沿原有事务流程更新，同时维护加密快照与目录文件，避免直接编辑目录导致归属校验失败；刷新不套用供应商草稿，不改 OAuth、配置绑定或对话。
- 官方默认模型下线时保留已应用记录的可读性；下次显式同步回退到可见官方模型，不再连带阻断共用记录的 Claude Code。未知注入标识仍拒绝加载。
- Anthropic Messages / Chat Completions 接入移除可选的 OpenAI 内置 `web_search` / `web_search_preview` 声明，并向模型明确说明原生搜索不可用，不得声称已联网。其余函数、自定义工具及原文保留，响应头和请求日志记录缺失能力。
- 强制搜索请求仍拒绝，返回 HTTP 400 能力错误；未支持的其他内置工具也返回准确的 400。Responses 接入完整保留原生搜索，不自动切换协议或官方账户。

验证：相关模型、目录刷新、跨协议、工具及状态保留测试通过；本机 npm Codex CLI `0.146.1` 和桌面附带后端实际加载生成的目录成功。原生 Codex 开启 `web_search="live"`，经模拟 Gemini Anthropic 上游完成请求，并保留客户端工具。未调用真实云端或消耗账户额度。

本机采用 `--keep-running` 更新下次启动入口，保留当前 ASS / Codex。正常重开 ASS 后更新目录和路由生效。
