# v0.4.7

修复协议检测结果与已接入路由不一致的问题，并缩短可用模型的连接测试。

- 已接入模型采用匹配其端点、密钥、请求头和网络的成功协议检测结果。此前检测结果只影响下一次同步，实际请求可能继续使用旧协议。调整不重写接入快照，不发布新增模型、端点或凭据草稿。
- 闪电连接测试、首次接入及模型保存后的协议寻找，得到一个完整成功流后结束。复查优先使用已成功协议，失败再查其他协议；完整能力实测仍独立检查全部协议。
- 临时失败保留历史成功证据，但本次成功的其他协议优先。超时仍为“未确认”，不伪报为“不支持”，不重放用户请求。
- 连接测试明确设置 512 token 小预算；协议探针加入唯一请求标记，避免把相同探针的重放视为新的生成验证。总耗时包括协议检测，详情单独显示“协议确认”。
- WOYAO Gemini Responses 返回明确错误，拒绝原生搜索与函数混用，且不接受通过 Responses 补充其提示的底层参数。混用时采用已有的搜索能力提示和日志机制，保留客户端工具；强制搜索仍返回能力错误。其他供应商的 Responses 原生搜索保持原样。

2026-10-21 本机实测中，部分固定探针和重放请求约 4–13 秒完成；绕过 ASS、直接向 WOYAO 发送的全新小型文本请求也出现 60 秒无 HTTP 响应。真实 Codex 的新任务仍未完成验证，不能据固定探针通过声称 Gemini 已恢复，也未确认是订阅额度问题。未采用缺乏稳定证据的输出上限、工具格式或取消信号改动。

相关协议选择、已应用 HTTP 路由、凭据隔离、草稿保留、取消、慢响应和诊断持久化回归，以及隔离 Electron IPC 检测流程通过。更新使用 --keep-running，新版下次正常启动生效，当前 ASS / Codex 保持运行。
