# 主题圆形揭幕

参考 [VitePress 官方主题切换示例](https://vitepress.dev/guide/extending-default-theme#on-appearance-toggle) 和 [Chrome 同文档 View Transitions 文档](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)，使用浏览器保存的整窗旧 / 新视图，不复制另一套 React 页面。

- 新主题在 `::view-transition-new(root)` 中由 `circle(0px)` 扩张，两种方向都让圆内显示新主题；旧主题在圆外保留。以整窗 / 实际快照盒较大尺寸的对角线 `D = hypot(width, height)` 为准，唯一目标半径为 `D * 2 + 96`，整段距离纳入同一曲线。这里判断的是半径而不是直径，两者使用同一 CSS 坐标单位。无默认交叉淡化、模糊或额外彩色描边。
- 圆心统一使用实际触发按钮中心，不随按钮内部点击点改变；鼠标、键盘、拖拽释放及自动模式相同。支持任意位置的按钮，不写死左下角坐标。
- 快照根层、分组及旧 / 新图像显式铺满可视窗口，清除默认分组位移；圆心按按钮中心相对窗口的百分比传入蒙版，不混用 DOM 像素与快照图像盒坐标。验证时还需要测最终绘制的圆心，而不只比对 keyframes 参数。
- 总时长 2000ms，offsets `[0, .98, 1]`：`cubic-bezier(.2,0,.55,1)` 一次扩张到完整大半径，后半段连续减速至零，最后 2% 保持完整帧。约 1800px → 3557px 这段包含在同一连续曲线内；速度验证覆盖全部 keyframe 段，并检查半径 80% → 99% 的真实耗时，不能只测第一段曲线或最终半径。外层 timeline 为线性，胶囊弹簧独立。
- 修复同色同步提前跳过快照的路径：已经提交新色后的系统 / 模式回声不取消在途揭幕；重复尺寸通知及 2px 内的舍入变化也不结束动画。
- 相同实际深浅色不重复揭幕；系统减少动态效果、隐藏窗口或不支持 API 时直接切换。自动模式保存 `system`，由实际系统变化触发揭幕。
- 快速连续操作取消在途快照并直接采用最后选择，不排队、不锁按钮。取消后的旧回调不允许覆盖新选择；窗口改变大小或隐藏时清理过渡。
- Chromium 快照可能把点击重定向到根节点；仅在过渡期间，把命中主题按钮或窗口按钮范围的输入交还原控件，保留真实点击坐标和拖拽指针。不会拦截其他内容，也不创建第二套可操作 UI。
- Windows 的原生 caption overlay 不属于浏览器快照，因此改为页面内同位置的最小化 / 最大化 / 还原 / 关闭按钮。它们和页面一起受圆形蒙版控制。按钮只通过固定白名单 IPC 操作 ASS 自己的窗口，关闭仍使用既有的隐藏到托盘逻辑；不停止路由或原生 harness。
- 弹窗遮罩从顶栏下方开始。原生 modal 将顶栏标记为不可交互时，仅向固定窗口按钮交还命中范围内的点击；不会穿透弹窗去切换主题或触发后台页面，也不会因窗口操作顺带关闭弹窗。

窗口按钮为页面内绘制，未实现 Windows 11 原生最大化按钮悬停时的贴靠布局菜单；不将基本最大化 / 还原验证视为此菜单的验证。

新增的是自动遵循系统 `prefers-reduced-motion` 的兼容处理，不增加“减少动态效果”设置项。

这套配色、主题胶囊和圆形切换已从当前源码提炼为项目内的 [best-light-dark-switching skill](../skills/best-light-dark-switching/SKILL.md)，包含独立可复制的参考代码。项目实际实现与用户要求是依据，skill 是提炼结果，不是要求项目套用的旧规范。

当前胶囊在全屏揭幕期间使用独立实时命名层，避免旧 root 截图遮住移动中的滑块；自动档包含日轮升沉、内光、地平线和海面倒影，装饰运动不占用滑块外层 transform。
