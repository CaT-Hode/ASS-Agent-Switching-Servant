# 账户与供应商接入分离 · v0.1.18

## 三个独立动作

| 动作 | 改变什么 | 不改变什么 |
| --- | --- | --- |
| 添加 / 移除官方账户卡片 | 该客户端可选的官方凭据引用 | 供应商、模型范围、已运行窗口 |
| 设为启动账户 | 下次启动所用账户 | 模型默认值、其他账户、当前进程登录 |
| 保存并确认同步供应商接入 | 此客户端纳入的供应商及其兼容模型 | 官方 OAuth、默认模型、其他客户端范围 |

Codex 只接受 OpenAI 官方 OAuth / API，Claude 只接受 Anthropic，DSH 只接受 DeepSeek API，OpenCode 只接受 Go / Zen API；pi 接受本机安装版本确认支持的 OAuth。对应服务使用严格 HTTPS 主机与路径白名单，不按品牌名或“OpenAI 兼容”协议推断官方身份。

## 模型来源与凭据

- 全局供应商中已启用、有 Key、协议兼容的模型默认进入接入范围。每个客户端按供应商整组开关；只读展开模型，移除默认模型和“启动模型”。配置修改先保存为草稿，不绑定或选择账户。
- DSH / OpenCode / pi 直写原生模型字段与凭据；Codex / Claude 使用独立已应用路由快照。恢复记录使用 Windows DPAPI 加密。
- 原生只读目录聚合与账户卡片白名单独立：被隐藏的其他供应商原生记录不会被删除，其声明的模型仍可查看。但不把其他 harness 的 OAuth 自动当作通用 API Key 注入。
- ChatGPT OAuth 与第三方 Key 不混用。Codex API-only 窗口的目录不含订阅回退模型；本地路由令牌请求订阅端点会被拒绝。Claude API 模型窗口与官方账户窗口分开；原生账户启动若遇到已知密钥 / 端点覆盖项会报错而非静默改计费身份。
- Claude 客户端使用 Messages；ASS 优先转发原生 Messages，DeepSeek 使用其官方兼容入口，其他 Chat Completions / Responses 供应商适配文本与函数工具。API 窗口通过完整 `供应商::模型` ID 选择，不声称 Claude 原生界面自动枚举全部第三方模型。跨协议图片 / 服务端工具和精确 token 计数不静默模拟。
- v0.1.24 起，DeepSeek / OpenCode Go / Zen 原生 API 凭据在资料查询或模型检测成功后可进入加密供应商目录，已配置的同地址同 Key 去重；对应原生目录卡片不重复展示。OAuth 不转换；不会因为发现供应商而自动同步到正在运行的客户端。

## 应用、启动、撤回

保存后显示“待同步”。同步需简短确认，遇到请求进行中、过期预览或受管字段外部改动时拒绝；不会强制重启客户端。配置“已写入”不代表运行中的客户端已重载。

新开的官方账户目录只继承上次已应用的模型字段；已有目录不因启动动作而更新。模型选择留在原生客户端，DSH 使用实际存在的 `web` profile。原生窗口不依赖 ASS 路由；依赖 ASS 代理的窗口按其实际传输方式登记退出保护。

关闭接入仅撤回 ASS 管理字段，保留账户、OAuth 刷新记录、用户插件和其他供应商。损坏的恢复记录或未知外部改动不会被盲目覆盖。多文件代理 / 原生事务均保留加密恢复记录，启动只读检查，确认同步时恢复。

## 旧数据迁移

旧版账户分离保存 `clients.before-account-separation.json`。v0.1.18 额外保存 `clients.before-provider-injection.json`，升级为 schema v3：

- `accountBindings / accountExclusions` 只控制官方账户卡片。
- `injections` 仅保存每个客户端的 `excludedProviders`。
- `selected` 只表示启动账户，不再决定模型注入。

旧的非官方绑定从账户页移除，供应商、Key、模型保留。旧版有任一模型被排除的供应商整体迁移为关闭，不扩大接入范围；旧默认模型选择移除。旧字段删除后不再反复导入。损坏、越界或较新版本配置拒绝覆盖。升级不自动修改生产原生配置，需用户确认同步。

项目级或企业托管策略仍可能限制原生客户端；配置文件可读不代表所有模型权限、订阅计费或完整 Agent 任务均通过实网验证。
