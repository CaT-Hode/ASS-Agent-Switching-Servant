# 动效与接入

## 复用边界

`assets/` 是从 ASS 的主题模块抽取的可独立参考实现：

- `theme-control.jsx`：太阳 / 月亮 / 黄昏 SVG、主题状态、指针和键盘入口。
- `theme-control.css`：必要语义 token、胶囊场景、低幅循环与快照样式；不包含 ASS 页面布局、logo 或供应商列表。
- `theme-motion.mjs`：跟手、边缘阻尼、临界阻尼弹簧及停靠点选择。
- `theme-reveal.mjs`：触发按钮中心、整窗快照、在途取消和受限输入恢复。

这些模板需要 React / React DOM，但纯 CSS 与两个 `.mjs` 可用于其他技术栈。不需要 ASS 后端、账户文件或任何网络服务。

## React 接入

将四份模板放在同一组件目录，导入 CSS。在客户端渲染入口提供已保存的 mode 和持久化回调：

```jsx
import { useState } from 'react';
import { ThemeControl } from './theme-control.jsx';
import './theme-control.css';

function ThemeSetting() {
  const [mode, setMode] = useState(() => localStorage.getItem('ass-theme') || 'system');
  return <ThemeControl value={mode} onChange={setMode} />;
}
```

模板沿用 `ass-theme` 作为示例存储键，接入目标应用时统一替换为已有键或现有设置层，不新增第二套互相覆盖的偏好来源。服务端渲染应用把 DOM 初始化放进客户端模块，提前应用保存值避免闪烁。

胶囊可以直接使用。不要给它和内部层叠加目标项目的通用 `transition: all` 或整按钮按压缩放；模板已用同一个呈现值驱动场景。

默认三个停靠点为 `light / system / dark`。需要双色版本时同时调整 `modes`、`themePositions`、`themeAtPoint`、释放投影的停靠点数、键盘边界及可访问状态；删除自动场景，滑块保留两端行程。不能只隐藏中间图标，仍让中间点击进入自动。

## 胶囊和全站切换是两套运动

胶囊是直接操控：临界阻尼弹簧从当前呈现位置与速度开始，按下立即可抓取，释放以短时采样速度投影到最近停靠点。ASS 参考频率为 28、越界阻力较强但不生硬停止。

圆形揭幕是一次性语义转换：使用全站旧 / 新快照，无弹性、无回弹、无过冲。默认 2000ms，单次扩张用非对称 `cubic-bezier(.2,0,.55,1)`，平滑起步，速度只有一个受控峰值，后半段连续减速至零。整个大半径都属于这条曲线，不在约半径一半的位置结束。不要把装饰循环、胶囊弹簧和整窗揭幕绑成相同节奏。

如果调整时长或曲线，检查实际每帧半径，尤其最后 100–200ms：不能在结束时突然补齐大块区域。普通菜单的短时长不直接套用到整窗蒙版。

### 整条速度曲线的调节

- 起步更快不等于起始速度跳变。保留 Bézier 的两个纵向控制值为 `0 / 1`，使两端速度为零；通过横向控制值分配加速与减速时间。峰值可以前移，但避免尖峰、二次加速和尾段回弹。
- 曲线与时长要一起调整。前段加速更早时可小幅增加总时长，把时间留给减速并限制峰值；不要只换缓动名称，也不要叠加全局与分段缓动。
- 横向比较使用同一可见半径和真实毫秒：第一 100ms 展开了多少、峰值速度 / 出现时间、可见阶段最后 200 / 150 / 100 / 50ms 的径向速度。不同总时长下，仅比较相同百分比进度会掩盖实际速度差异。
- 从零到最终半径使用一条连续单峰曲线；末尾只保持，不再追加第二次扩张。检查所有 keyframe 段，不能只验证第一段缓动。把后续大段半径压进短时间，会在已经减速后形成第二个速度尖峰。
- 区分时间进度、半径进度和屏幕覆盖面积。至少量出半径 80% → 99% 的实际耗时与速度，并检查完整时间轴后半段没有再加速；仅到达最终半径、保持数帧不能证明观感平滑。

## 清晰圆形揭幕

参考 [VitePress appearance toggle](https://vitepress.dev/guide/extending-default-theme#on-appearance-toggle) 与 [Chrome 同文档 View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)。不要复制第二套 React 树或整个 DOM 作为遮罩。

1. 在实际用户入口调用 `document.startViewTransition`；不要因为任意状态刷新都触发一次整窗动画。
2. 捕获旧配色后，在更新回调中应用所选主题 / 实际 `color-scheme`，React 需要时在该回调中提交状态。自动模式先固定旧实际配色，再处理系统变化，避免媒体查询抢先把旧快照变成新颜色。
3. 在 `ready` 后，仅动画 `::view-transition-new(root)` 的 `clip-path`，旧快照保持不透明在下层。根快照层固定铺满窗口，根分组、图像对及旧 / 新图像显式设为 `inset: 0; width: 100%; height: 100%`，分组取消默认位移；图像填充该整窗盒。关闭默认淡化及混合模式，边缘不加 blur、羽化或彩色光圈。
4. 鼠标、键盘、拖拽释放、系统主题事件都使用实际触发按钮的 `getBoundingClientRect()` 中心，不是按钮内部任意鼠标点，也不硬编码左下角。将中心换算为 `x / viewportWidth * 100%`、`y / viewportHeight * 100%` 后传入圆形蒙版，使圆心与快照层使用同一参照盒。按钮搬到右上角时圆心随按钮搬动。
5. 在快照就绪时读取实际根图像盒，尺寸取它与整窗的较大值。以完整对角线 `D = hypot(width, height)` 为准，唯一目标半径为 `D * 2 + 96`，严格大于完整窗口对角线。比较半径而非直径，并使用同一 CSS 坐标单位；不可只保留约一个对角线的半径来回避后段曲线问题。
6. keyframes 的 offsets 为 `[0, .98, 1]`：用一条 S 形曲线从零扩张到完整大半径，最后 2% 重复该帧。外层 timeline 用 `linear`，S 曲线仅放在第一帧；不要叠加两次缓动。核验经过任何中间半径时速度连续、继续到最大半径后才结束；取消的动画不强行追到最大值。

这些数值是参考默认值。调整时长、屏外余量或曲线时保持上述连续性，不能把一次失效的旧实现当成必须保留的分段结构。

两个方向都从小圆扩张，让圆内显示新主题；不在浅→深时换成“旧主题收缩”的另一套规则。

## 状态和清理

- 分开保存 `mode = light / dark / system` 与 `resolved = light / dark`。只有实际配色变化才播放揭幕。
- 只允许一套在途快照。连续切换取消旧快照并直接提交最新选择，优先响应，不排队等待整段动画。
- 新颜色已经提交后的同色系统 / 模式同步，只更新语义状态，不跳过正在进行的快照。尚未提交时的新选择仍需要代际替换，不能让旧请求稍后写回。
- `skipTransition()` 仍可能执行更新回调；使用代际标识和 `applyOnce`，被替代的选择不能稍后重新写回。
- 结束、取消、失败均清除 `fill:both` 的 WAAPI 动画，否则后续过渡可能复活旧蒙版。实际窗口明显变大 / 小或隐藏时清理，重复尺寸事件及微小舍入变化不能提前结束揭幕。
- 不支持 API、隐藏或系统 `prefers-reduced-motion: reduce` 时直接应用主题，不改变持久化语义。
- 某些 Chromium 快照会把命中测试交给根节点。模板只在过渡期间向已存在、实际命中的主题控件交还输入；弹窗挡住主题按钮时不能穿透。不要转发到任意页面选择器。

## Electron 窗口区域（仅目标项目需要时）

Windows 原生 caption overlay 不在浏览器快照中。先明确需求：保留原生窗口按钮，接受它们不参加圆形遮罩；或者改成页面内绘制，加入快照，但需要实现窗口控制、状态订阅和原生能力取舍。

页面内按钮仅通过固定白名单 IPC 操作自己的窗口：最小化、最大化 / 还原、既有关闭行为。不要把“关闭到托盘”改成结束路由，不操作其他 harness。窗口状态使用顺序号抵御异步旧回复。

原生 modal 的 inert / backdrop 不应挡住 caption：遮罩从顶栏下方开始，必要时只向三颗固定窗口按钮恢复命中输入，不顺带关闭弹窗。浏览器中不需要这套特殊处理。仅绘制按钮不等于拥有 Windows 11 原生悬停贴靠菜单，需如实说明。

## 一轮验证

先运行 `node scripts/check-reveal.mjs`。脚本不依赖浏览器或第三方包，会调用参考模块取得真实输出 keyframes，再以 1ms 间隔计算完整轨迹；支持通过第一个参数检查同接口的目标模块。它检查单一速度峰值、尾段持续减速、最终半径和零末速，输出首 100ms 距离、峰值速度、半径 80% / 90% / 99% 的时间与速度。它不证明浏览器正确绘制或动画未被外部提前取消。

先区分两种窗口：采样测试可以暂停、跳转时间、提前完成以检查指定帧，但必须标明测试身份；连续演示不得调用这些控制方法。用 `requestAnimationFrame` 读取实际半径与动画时间，计算连续帧的速度和覆盖过程。存在测试脚本跳帧不代表产品曲线没有问题；两者分别核验，不用强制设置最终时间或“到达终点”替代速度验证。

先完成相关编辑，再一起检查真实界面：浅→深、深→浅、连续反向、拖拽中抓取、自动系统切换、按钮中心圆心、弹窗下的窗口按钮、缩放 / 隐藏、减少动态效果。采样实际 `clip-path` 半径及径向速度，确认全程单峰、半径达到 80% 后继续减速、最终完整覆盖四角，以及同色回声不会跳过动画。

截图只能证明形态；运动速度需要真实动画的计算进度 / 连续帧证据。圆心要验证最终绘制结果：可临时使用半径小于按钮距窗口边缘的圆形，在纯色旧 / 新测试快照中测像素边界中心，与真实按钮中心比对。覆盖长页面、滚动及系统 / 页面缩放；Electron 页面缩放时优先使用 `webContents.capturePage()` 获取原生窗口画面，避免 CDP 截图视口自身的缩放裁切影响判断。不要用静态 build 成功代替交互验证，不调用目标项目之外的账户或服务。

### 出现末段跳变时

- 先确认正在运行的构建确实包含当前代码，检查自然播放是否到达最终半径，以及是否触发 `cancel / skipTransition / finished / resize / visibilitychange`。记录触发时刻的真实半径，不能靠延长末尾保持帧补救提前结束。
- 若速度再次上升，检查所有 keyframe 的距离、offset 和 easing；把完整大半径纳入同一曲线，删除后接的快速扩张。修改后检查整条轨迹，尤其各段连接处。
- 若计算半径平滑而画面跳变，核对实际快照盒、圆心、滚动与系统 / 页面缩放，并用连续帧检查四角。半径单位是 CSS px；不能混用设备像素，或仅靠计算参数宣称绘制正确。
- 用户说“覆盖约 80%”时，检查窗口内实际覆盖区域；半径 80% 的尾速只能证明径向轨迹。在角落起圆且屏外余量较大时，画面可能早于半径终点完全覆盖。
- 若观察窗口是采样测试，标记暂停与 seek 的操作，再用独立连续播放复核；测试脚本会跳帧这一事实不能代替产品曲线和状态清理的检查。
